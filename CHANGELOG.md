## [Unreleased]

### Added

#### Главная: заявки водителя и досье пассажира (нативный tgui)

- **Backend**: новый эндпоинт `GET /api/v1/bookings/driver` — сводка pending-заявок по всем активным **будущим** поездкам текущего водителя, сортировка по времени отправления, вложенный пассажир с аватаром и рейтингом. Ответ валидируется контрактом (`bookingSchema`), fail-closed. Патч-маршруты статусов брони без изменений — решение принимается тем же `PATCH /bookings/:id/status`.
- **Секция «Рассмотрите заявки»** на главной (`DriverRequestsSection`): нативный tgui — `Section` + `Cell` (аватар пассажира 48 с `Avatar.Badge` рейтинга, subtitle «дата · время · место №N»), единственная иконка-действие **«+»** (`IconButton` bezeled) и `ButtonCell` «Показать все (N)» при >3 заявок. Секция скрыта, если заявок нет. Тап по ячейке — страница заявок поездки, тап по «+» — досье в модалке. Inline-кнопки «принять/отклонить» прямо в списке отклонены как небезопасные (случайный тап).
- **Досье пассажира в нижней модалке** (`PassengerRequestModal`): контролируемый vaul-`Modal` (`open`/`onOpenChange` — программное закрытие после решения). Тело: Avatar 96 с бейджем рейтинга, статистика «★ N · поездки · отзывы», маршрут/время/цена/комментарий брони, **2 последних отзыва о пассажире** (`targetRole = "passenger"`; `useUserReviewsQuery` с опцией `enabled` — ленивая загрузка только при открытой модалке). Решение — «Одобрить заявку» (filled) / «Отказать» (bezeled, destructive-цвет): `ConfirmAction` не нужен, тап по «+» ничего не решает, отказ — осознанное действие. Кнопки блокируются на время мутации (`pendingAction`-состояние), haptic + toast «Заявка принята/отклонена».
- **`useUserReviewsQuery(userId, { enabled })`** — добавлена опция `enabled` (обратная совместимость: по умолчанию как раньше). В секции заявок ленивость обеспечивается пустым `userId` при закрытой модалке (запрос disabled, пока пассажир не выбран).

#### Dev-стенд: сид для DEV-аккаунта Telegram (`u-dev`, `telegramUserId 9800001`)

- **Поездки водителя**: `t-dev-1` (3 pending-заявки), `t-dev-2` (1 confirmed + 2 pending — демо и «Ваша поездка», и «Показать все (N)»), `t-dev-past-1` (прошедшая completed).
- **Брони пассажира**: две будущие confirmed (`t-dev-3`, `t-dev-5`) → секция «Ваши поездки» во множественном числе; одна будущая pending (`t-dev-4`) → «Ожидают подтверждения»; прошедшая (`t-dev-past-2`) как источник отзыва.
- **5 pending-заявок** суммарно → секция «Рассмотрите заявки» показывает 3 + кнопку «Показать все (5)». Заявки с комментариями **и без** — покрыты оба пути рендера ячейки; у пассажиров заявок есть отзывы, поэтому досье в модалке показывает реальные отзывы, а не заглушку.
- **3 уведомления** DEV-аккаунту (заявка от пассажира, два подтверждения броней) и 2 отзыва о нём (r-29/r-30) — профиль и бейдж рейтинга не пустые.
- Учтены ограничения сида: `MAX_SEATS = 3` (`seatsTotal` не больше 3), уникальность активных мест/пассажиров внутри поездки, а автор отзыва обязан быть confirmed-пассажиром этой поездки (отсюда прошедшие поездки `t-dev-past-*`), pending-брони — с `expiresAt` по TTL 24ч, как ставит рантайм.

### Changed

#### Главная — только нативные компоненты tgui (без кастомного CSS)

- Блок «Куда поедем?»: `Multiselect` (типинг + Enter) заменён на `CitySelectField` — нативный tgui `Select` с системным дропдауном ОС. Старый `CityPickerField` сохранён для формы создания поездки.
- Брони главной разделены на **две секции по статусу** вместо одной «Ближайшей поездки»: «Ваша поездка»/«Ваши поездки» (confirmed) и «Ожидают подтверждения» (pending). Бронь рендерится нативной ячейкой `BookingCell` (`Cell multiline` вместо `Banner`): аватар водителя 48 с `Avatar.Badge` рейтинга, subtitle — маршрут (`Subheadline`), содержимое — дата и цена (`Badge`), description — `Blockquote` с комментарием водителя к поездке **только у confirmed** (комментарий пассажира на главной не показывается — это текст для водителя, он виден в досье заявки), after — `IconButton`-шеврон на страницу поездки. Статус задан заголовком секции и не дублируется в ячейке (a11y — смысл текстом). Вычисление обёрнуто в `useMemo`.
- «Преимущества Едем» убраны с главной (статичный маркетинговый блок для уже зарегистрированных пользователей; кандидат на переезд в Onboarding).
- CTA «Едете на машине?» переведён на нативный `Placeholder` (header/description/action), профиль-бар — рейтинг нативным `Badge type="number"`.

### Fixed

- **Семантика `booking.seat` по всему приложению.** `seat` — это **порядковый номер места на схеме** (1..MAX_SEATS), бронь всегда ровно на 1 место. Исправлены ложная плюрализация («2 места» для места №2) и **искажение цены** `trip.price * booking.seat` (место №2 показывалось за 900 ₽ вместо 450 ₽): `PassengerRequestModal`, `DriverRequestsSection`, `TripDetailsPage` («Вы записались»), `TripsPage` (блок цены и «взнос ~N ₽»), `HomePage` (в ячейке брони цена выводится без умножения на номер места). Хелпер `formatSeats` (плюрализация количества) удалён — заменён на `formatSeatNumber(seat)` → «место №N». Корректные места не тронуты: `TripRequestsPage/Modal` («место N»), `RideRequests*` (`request.seats` — реальное количество у заявок на поиск поездки). Бэкенд считал верно (`price: trip.price`).
- **`utils/bookingSplit.ts`** (новый модуль, DOM-free): `splitBookingsByStatus`, `isUpcomingBooking`, `confirmedSectionHeader`, `formatSeatNumber`. Попутно исправлен баг прежней логики главной: бронь без валидной даты отправления считалась «будущей» — теперь активной не считается.
